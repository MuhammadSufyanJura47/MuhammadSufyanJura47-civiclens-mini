Build an original project that uses open-source or open-weight AI as an important part of how it works.
Teams could create an agent skill, build with an open-weight large or small language model, or build or adapt an open-source model harness. These are examples within one challenge, and teams may combine them.
ONE CHALLENGE • MANY WAYS TO BUILD
Agent Skills, open-weight models, and model harnesses are not separate competitions. They are different approaches teams may use within the same challenge.

2. What You Can Build
Your team is free to choose its own idea. The following are examples, not a mandatory list:
•	An AI-powered developer or productivity tool.
•	A local or self-hosted AI assistant using an open-weight model.
•	An Agent Skill that gives an agent a useful capability.
•	A document, knowledge, research, education, or workflow assistant.
•	An AI application that uses an open-weight LLM/SLM as a core component.
•	An original model harness or a meaningful adaptation of an existing open-source harness.
•	A project combining an Agent Skill, open-weight model, and/or model harness.
•	A completely different idea—as long as it satisfies the challenge requirements.
3. Suggested Domains
To help teams who want a starting point, organizers may provide the following five domains. These domains are optional: teams may build in one of them, combine them, or choose a different problem entirely.
DOMAIN	AREA	EXAMPLE DIRECTION
01	HEALTH & WELLNESS	Assist with information, workflows, accessibility, prevention, or healthcare-adjacent tasks. Avoid making unsupported medical diagnoses or replacing professional medical advice.
02	EDUCATION	Build learning assistants, study tools, tutoring workflows, educational content tools, or tools that improve access to knowledge.
03	DEVELOPER & OPEN SOURCE	Create coding assistants, repository tools, documentation agents, issue/PR workflows, testing tools, or other developer productivity solutions.
04	COMMUNITY & SOCIAL GOOD	Solve a practical problem for communities, accessibility, public services, local organizations, or social impact.
05	BUSINESS & PRODUCTIVITY	Build tools for research, documents, operations, automation, customer workflows, knowledge management, or everyday productivity.

4. MUST-HAVE Requirements
These are mandatory.
A submission that fails a mandatory requirement may be considered ineligible for judging.

01	Open-source or open-weight AI must be an important part of the project.
The AI component must contribute meaningfully to how the project works. A superficial AI feature is not enough.

02	The project must be original.
Teams must contribute meaningful original work. Existing open-source libraries and models may be used as building blocks, subject to their licenses.

03	The project must be published in a public GitHub repository.
Judges must be able to access the source code and review the project.

04	The repository must use an open-source license.
Include a recognized open-source license in the repository. Examples include MIT, Apache-2.0, BSD, or GPL-family licenses.

05	An Agent Skill entry must comply with the Agent Skill Open Standard.
If the project is submitted as an Agent Skill, the implementation must follow the applicable Agent Skill Open Standard requirements.

06	A model-harness entry must include original implementation or meaningful changes.
Simply configuring, renaming, wrapping, or lightly modifying an existing open-source harness does not qualify as a meaningful harness contribution.

5. What Counts as 'Important AI Usage'?
The open-source or open-weight AI component should be central enough that removing it would substantially change the project's purpose or functionality.
•	Good: an open-weight model performs the core reasoning, generation, classification, extraction, coding, or agent behavior.
•	Good: an Agent Skill provides a meaningful capability to an AI agent.
•	Good: a model harness controls, routes, evaluates, or orchestrates open models and contains original engineering work.
•	Weak: an otherwise normal application only adds an AI-generated greeting or a minor text-generation feature.
•	Weak: the project uses a closed proprietary model as its actual core while an open model is only mentioned or used incidentally.
6. Originality & Use of Existing Projects
Open source is encouraged. Teams do not need to reinvent every dependency.
•	You may use open-source libraries, frameworks, models, datasets, APIs, SDKs, and other legitimate dependencies.
•	You may start from an existing open-source project when the challenge track permits it, but your contribution must be clearly meaningful.
•	Do not submit a tutorial copied with minimal changes.
•	Do not submit a fork with only cosmetic edits, configuration changes, or renamed files.
•	Clearly acknowledge major third-party components in your README.
•	Respect all third-party licenses and attribution requirements.
7. Model-Harness Rules
A model-harness project is welcome, but the bar is higher than simply connecting an existing tool to a model.
•	The repository must contain an original implementation OR meaningful changes to an existing open-source harness.
•	Document exactly what your team implemented or changed.
•	Explain why the changes matter and what problem they solve.
•	A simple configuration, prompt change, UI skin, or model swap alone should not be presented as a new harness.
•	If adapting an existing harness, provide attribution and comply with its original license.
8. Agent Skill Rules
If your project includes an Agent Skill, the skill must comply with the Agent Skill Open Standard.
•	The skill should have a clearly defined purpose and capability.
•	The repository should make the skill's intended usage understandable.
•	Include the necessary skill files/instructions and supporting implementation.
•	Provide at least one practical example demonstrating the skill.
•	Do not claim compliance without actually following the standard's required structure and conventions.
9. Submission Requirements
Each team should submit the following before the submission deadline announced by the organizers:
•	Public GitHub repository URL.
•	Project name and short description.
•	Team member names.
•	Chosen domain, if using one of the suggested domains.
•	Description of the open-source/open-weight AI technology used.
•	Explanation of why AI is an important part of the project.
•	Instructions for running or testing the project.
•	Open-source license included in the repository.
•	Short demo or presentation during the final judging session, if requested by organizers.
•	For Agent Skills: identify the Agent Skill Open Standard compliance.
•	For model harnesses: identify the original implementation or meaningful changes made by the team.

11. Team & Collaboration Rules
•	All listed team members should make a meaningful contribution.
•	Teams may use legitimate open-source tools and AI-assisted development tools.
•	Participants are responsible for understanding and complying with the licenses of code, models, datasets, and other assets they use.
•	Do not include secrets, private API keys, passwords, tokens, or other sensitive information in the public repository.
13. Build-Time Expectations
•	The project should be demonstrable within the event's available build period.
•	A smaller working prototype is better than an ambitious project that cannot be demonstrated.
•	Teams should prioritize a functional core feature, then add polish if time allows.
•	If a team uses a pre-existing project, the original work and the team's contribution must be clearly distinguishable.
14. Ineligibility / Disqualification
Protect the spirit of the challenge.
The organizers reserve the right to mark a submission ineligible where the mandatory requirements are not met or where the submission materially misrepresents the team's work.

•	No public GitHub repository.
•	No open-source license.
•	Open-source/open-weight AI is only incidental or superficial.
•	Copied or substantially reproduced work without meaningful original contribution.
•	A model-harness entry without an original implementation or meaningful changes.
•	An Agent Skill entry that does not comply with the applicable Agent Skill Open Standard requirements.
•	Use of proprietary material or third-party code in violation of its license.
•	Submission contains malicious code, secrets, credentials, or content that creates an unacceptable security or safety risk.
•	Misrepresentation of contributions, authorship, or technology used.

17. Quick FAQ
Q: Do I have to use one of the five domains?
A: No. The five domains are suggested starting points. Your team may build something outside them.
Q: Do I have to build an Agent Skill?
A: No. An Agent Skill is one possible approach within the challenge.
Q: Do I have to train my own model?
A: No. You can build with an existing open-weight model. Training a model is optional.
Q: Can I use open-source libraries?
A: Yes. Open source is encouraged. Follow the applicable licenses and make sure your own contribution is meaningful.
Q: Can I combine approaches?
A: Yes. Teams may combine Agent Skills, open-weight models, model harnesses, and other open-source components.
Q: Can I use a proprietary AI tool during development?
A: Development tools may be used where permitted by the event rules, but the submitted project itself must satisfy the challenge's open-source/open-weight AI requirement.
Q: What if my project is not fully production-ready?
A: That's okay. A functional, well-demonstrated prototype is appropriate for a mini-hackathon. Focus on a working core experience.
